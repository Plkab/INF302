Estimation de l'angle d'inclinaison par Filtre Complémentaire¶

1. Le Problème fondamental : Estimer l'État caché¶

Notre objectif est unique : estimer en temps réel l'angle d'inclinaison $\theta$ (le tangage) d'un système mobile (robot, drone, balance).

Cet angle est une variable d'état que nous ne pouvons pas mesurer directement avec une précision parfaite. Nous disposons uniquement de capteurs brutiés. Le défi est de construire un estimateur qui combine les informations disponibles pour minimiser l'erreur d'estimation.

L'estimateur que nous allons utiliser s'appelle le Filtre Complémentaire. Il s'agit d'une technique de fusion de capteurs appliquée à l'estimation d'état.

Pourquoi un simple capteur ne suffit-il pas pour estimer $\theta$ ?¶

  • Avec un accéléromètre seul : L'angle estimé $\hat{\theta}_{acc}$ est très bruité. Les vibrations et les accélérations du mouvement polluent le signal. L'estimation est instable à court terme.
  • Avec un gyroscope seul : On estime l'angle en intégrant la vitesse $\omega$ ($\hat{\theta}_{gyro} = \int \omega \, dt$). Le moindre biais (offset) s'accumule et fait dériver l'estimation vers l'infini en quelques secondes. L'estimation est instable à long terme.

Solution : Combiner les deux pour obtenir une estimation $\hat{\theta}$ qui soit à la fois précise à court terme (fluide comme le gyroscope) et stable à long terme (ancrée comme l'accéléromètre).

2. Modélisation pour l'Estimation¶

Pour estimer $\theta$, nous devons définir comment l'état évolue et comment nous l'observons.

2.1. Équation d'évolution (Prédiction)¶

La dynamique de l'angle est régie par la vitesse angulaire $\omega$ (mesurée par le gyroscope) :

$$ \theta(t) = \theta(t-1) + \omega(t) \cdot \Delta t $$

C'est notre modèle de prédiction. Il est précis sur des durées courtes.

2.2. Équation d'observation (Correction)¶

L'accéléromètre nous donne une observation directe de l'angle, mais bruitée :

$$ \theta_{acc}(t) = \theta(t) + \text{bruit}(t) $$

C'est notre référence absolue. Elle est fiable en moyenne sur le long terme.

2.3. Structure de l'Estimateur¶

Le filtre complémentaire suit une architecture classique d'estimateur :

  1. Prédiction : On intègre la vitesse angulaire du gyroscope pour avancer dans le temps.
  2. Correction : On tire doucement l'estimation vers la valeur de l'accéléromètre pour corriger la dérive.

L'équation de cet estimateur s'écrit :

$$ \boxed{\hat{\theta}(t) = \alpha \cdot \big(\hat{\theta}(t-1) + \omega \cdot \Delta t\big) + (1 - \alpha) \cdot \theta_{acc}} $$

Où :

  • $\hat{\theta}(t)$ est l'estimation fusionnée à l'instant $t$.
  • Le terme $\big(\hat{\theta}(t-1) + \omega \cdot \Delta t\big)$ est la prédiction par le gyroscope.
  • $\theta_{acc}$ est la mesure corrective issue de l'accéléromètre.
  • $\alpha$ est le gain de l'estimateur ($0 < \alpha < 1$). Il règle la confiance accordée à la prédiction par rapport à la correction.

3. Réglage du Gain $\alpha$ pour une Estimation Optimale¶

Le réglage de $\alpha$ détermine la bande passante de l'estimateur. On le calcule à partir d'une constante de temps $\tau$ (en secondes) :

$$ \alpha = \frac{\tau}{\tau + \Delta t} $$

Interprétation pour l'estimation :¶

  • Si le mouvement dure moins de $\tau$ secondes : L'estimateur fait confiance à la prédiction du gyroscope (il suit les mouvements rapides).
  • Si le mouvement dure plus de $\tau$ secondes : L'estimateur commence à douter du gyroscope et se fie progressivement à l'accéléromètre pour corriger sa dérive.

Exemple concret pour un robot qui bouge vite (drone) :

  • Fréquence d'estimation : 100 Hz ($\Delta t = 0.01$ s).
  • Constante de temps choisie : $\tau = 0.5$ s (le gyroscope pilote l'estimation pendant 0.5s avant d'être corrigé).
  • Calcul : $\alpha = \frac{0.5}{0.5 + 0.01} \approx 0.9804$.

Règle d'or en estimation : La période d'échantillonnage $\Delta t$ doit être stable (sans variation de temps entre deux calculs), sous peine de dégrader gravement la qualité de la prédiction.

4. Implémentation de l'Estimateur¶

Voici le cœur de l'estimateur. Il ne stocke qu'une seule variable : l'estimation précédente $\hat{\theta}(t-1)$.

#include <math.h>

// Paramètres de l'estimateur
#define DT 0.01f               // Pas de temps (100 Hz)
#define TAU 0.5f               // Constante de temps
#define ALPHA (TAU / (TAU + DT)) // Gain de l'estimateur (~0.98)
#define RAD_TO_DEG 57.2958f

// État de l'estimateur (la variable que l'on estime)
static float theta_estime = 0.0f; 

/**
 * @brief Fonction d'estimation de l'angle.
 * @param gyro_deg_s  Vitesse angulaire mesurée (en degrés/s).
 * @param acc_y       Accélération sur l'axe Y (en g).
 * @param acc_z       Accélération sur l'axe Z (en g).
 * @return float      Nouvelle estimation de l'angle.
 */
float estimer_angle(float gyro_deg_s, float acc_y, float acc_z) {
    // 1. Observation brute via l'accéléromètre
    float theta_obs = atan2f(acc_y, acc_z) * RAD_TO_DEG;

    // 2. Étape de prédiction (Gyroscope)
    float theta_pred = theta_estime + (gyro_deg_s * DT);

    // 3. Étape de correction (Fusion)
    //    On pondère la prédiction par ALPHA et l'observation par (1-ALPHA)
    theta_estime = (ALPHA * theta_pred) + ((1.0f - ALPHA) * theta_obs);

    return theta_estime;
}

5. Simulation Python : Validation de l'Estimateur¶

Pour valider notre estimateur, nous allons simuler un angle réel (la vérité terrain) et le comparer à notre estimation $\hat{\theta}$ issue du filtre.

Nous allons volontairement polluer :

  • Le gyroscope avec un biais (pour voir la dérive).
  • L'accéléromètre avec un bruit blanc (pour voir les vibrations).

Le graphique suivant va prouver que notre estimateur (bleu) suit parfaitement la vérité (noir), contrairement aux capteurs pris isolément.

import numpy as np
import matplotlib.pyplot as plt

# --- Paramètres de la simulation ---
fs = 100.0                 # Fréquence d'échantillonnage (Hz)
dt = 1.0 / fs              # Pas de temps (0.01 s)
T = 15.0                   # Durée de la simulation (15 secondes)
t = np.arange(0, T, dt)
N = len(t)

# --- Réglage de l'estimateur ---
tau = 0.5                  # Constante de temps
alpha = tau / (tau + dt)   # Gain de l'estimateur (~0.9804)

# --- 1. VÉRITÉ TERRAIN (l'angle réel que l'on cherche à estimer) ---
# Un mouvement oscillant complexe (comme un tangage de drone)
true_angle = 20.0 * np.sin(2 * np.pi * 0.4 * t) + 5.0 * np.sin(2 * np.pi * 1.2 * t)

# --- 2. SIMULATION DES CAPTEURS (entrées de l'estimateur) ---

# Gyroscope : Dérivée de l'angle + BIAIS (0.3 °/s) + petit bruit
gyro_bias = 0.3  
gyro_noise = 0.15
true_gyro = np.gradient(true_angle, dt)  # Dérivée exacte
meas_gyro = true_gyro + gyro_bias + np.random.normal(0, gyro_noise, N)

# Accéléromètre : Angle réel + GROS bruit haute fréquence (vibrations)
accel_noise = 4.0  
meas_accel = true_angle + np.random.normal(0, accel_noise, N)

# --- 3. EXÉCUTION DE L'ESTIMATEUR (Filtre Complémentaire) ---
estimated_angle = np.zeros(N)
estimated_angle[0] = meas_accel[0]  # Initialisation sur l'observation

for i in range(1, N):
    # Prédiction (gyroscope) + Correction (accéléromètre)
    pred = estimated_angle[i-1] + meas_gyro[i] * dt
    estimated_angle[i] = alpha * pred + (1.0 - alpha) * meas_accel[i]

# --- 4. AFFICHAGE DES RÉSULTATS DE L'ESTIMATION ---
plt.figure(figsize=(15, 9))

# La Vérité
plt.plot(t, true_angle, 'k-', linewidth=3, label='Angle Réel (Vérité à estimer)')

# L'Accéléromètre brut (Observation)
plt.plot(t, meas_accel, 'g.', alpha=0.3, markersize=1.5, label='Mesure Accéléromètre (bruitée)')

# Le Gyroscope intégré seul (Prédiction sans correction)
gyro_only = np.zeros(N)
for i in range(1, N):
    gyro_only[i] = gyro_only[i-1] + meas_gyro[i] * dt
plt.plot(t, gyro_only, 'r--', linewidth=1.5, label='Intégration Gyroscope seul (Dérive)')

# NOTRE ESTIMATION (le résultat du filtre)
plt.plot(t, estimated_angle, 'b-', linewidth=2.5, label='Estimation par Filtre Complémentaire')

# Mise en forme
plt.title("Estimation de l'angle $\hat{\theta}$ vs Vérité Terrain", fontsize=16)
plt.xlabel("Temps (secondes)")
plt.ylabel("Angle (degrés)")
plt.legend(loc='upper right')
plt.grid(True, alpha=0.3)
plt.xlim(0, T)
plt.ylim(-35, 35)

# Annotations
plt.annotate('Dérive catastrophique\ndu gyroscope', xy=(9, 20), xytext=(5, 25),
             arrowprops=dict(facecolor='red', shrink=0.05), fontsize=10, color='red')
plt.annotate("L'estimation suit\nparfaitement la réalité", xy=(10, -15), xytext=(6, -25),
             arrowprops=dict(facecolor='blue', shrink=0.05), fontsize=10, color='blue')

plt.show()

# --- 5. MÉTRIQUES DE QUALITÉ DE L'ESTIMATION ---
erreur = np.abs(estimated_angle - true_angle)
print(f"=== Performances de l'Estimateur (α = {alpha:.4f}) ===")
print(f"Erreur moyenne d'estimation : {np.mean(erreur):.2f} °")
print(f"Erreur maximale d'estimation : {np.max(erreur):.2f} °")
print(f"Écart-type de l'erreur : {np.std(erreur):.2f} °")

6. Analyse des Résultats et Limites de l'Estimateur¶

Ce que le graphique nous apprend :¶

  1. L'estimation (bleue) est presque parfaitement superposée à la vérité (noire). L'objectif d'estimation est atteint.
  2. L'intégration seule du gyroscope (rouge) diverge à cause du biais de 0.3°/s. Elle est inutilisable pour une estimation à long terme.
  3. L'accéléromètre seul (vert) est tellement bruité qu'il rendrait le pilotage d'un drone impossible.

Pourquoi cet estimateur est-il efficace ?¶

Parce qu'il utilise deux sources d'information complémentaires :

  • La prédiction (gyroscope) est fiable pour les hautes fréquences (mouvements rapides).
  • La correction (accéléromètre) est fiable pour les basses fréquences (tendance lente).

Le gain $\alpha$ agit comme un filtre qui laisse passer les hautes fréquences du gyroscope et les basses fréquences de l'accéléromètre.

Les limites inhérentes à cet estimateur (très important à savoir) :¶

  • Il est monodimensionnel : Il estime un seul angle (le tangage). Pour le roulis, on fait pareil sur l'axe X. Pour le lacet (Yaw), il faut un magnétomètre.
  • Il est statique : Le gain $\alpha$ est fixe. Si le robot subit une accélération linéaire prolongée (ex : forte accélération en voiture), l'accéléromètre ne mesure plus la gravité mais la somme gravité+accélération. L'estimation s'en trouvera faussée jusqu'à ce que l'accélération cesse.
